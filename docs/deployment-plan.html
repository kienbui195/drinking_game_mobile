Kế hoạch push GitHub và deploy Linux

Phương án đầu tiên dùng một VPS Linux chạy Docker Compose. Caddy phục vụ web và cấp HTTPS; API NestJS và MySQL chỉ được truy cập trong mạng container. Đây là kế hoạch cùng cấu hình mẫu, chưa phải xác nhận đã deploy server thật.

Kiến trúc đích

play.example.com → Caddy → web Expo đã build.
api.example.com → Caddy → NestJS/Socket.IO → MySQL 8.4.

Expo Go hoặc APK kết nối trực tiếp API HTTPS. Máy chủ mở cổng 80/443 và SSH; không publish 3000 hay 3306. Một backend instance phù hợp MVP; restart có thời gian gián đoạn ngắn, client reconnect và phục hồi từ MySQL.

File đã chuẩn bị Vai trò
compose.production.yaml Stack production riêng, image gắn RELEASE_TAG, health check và giới hạn log.
apps/mobile/Dockerfile Build web với URL API thật rồi đóng gói cùng Caddy.
deploy/Caddyfile Hai domain, HTTPS tự động và reverse proxy WebSocket.
.env.production.example Mẫu domain, email ACME, mật khẩu MySQL và release tag.

Compose local và production là hai file độc lập. Không ghép hai file bằng nhiều cờ -f vì file local publish các cổng phục vụ phát triển.

1. Đưa code lên GitHub

Thư mục hiện chưa có Git repository. Tên repository và public/private cần được chọn trước. Các lệnh dưới đây là hướng dẫn thực hiện, chưa được chạy để tạo remote hoặc push. 

# Tại thư mục gốc dự án
git init -b main
git status --short
git check-ignore .env apps/mobile/.env.local

# Kiểm tra file sẽ đưa vào lịch sử, gồm cấu hình, source, lockfile, tests và docs.
git add .gitignore .dockerignore .prettierignore .prettierrc.json AGENTS.md package.json package-lock.json compose.yaml compose.production.yaml .env.example .env.production.example playwright.config.ts apps packages tests deploy docs
git diff --cached --stat
git diff --cached
git commit -m "feat: bootstrap multiplayer drinking game"

gh auth login
gh repo create OWNER/drinking-game-mobile --private --source=. --remote=origin --push
git tag v0.1.0
git push origin v0.1.0

Thay OWNER bằng tài khoản/organization thật. Chuyển --private thành --public nếu đã quyết định công khai. File .env, .env.local, .env.production, node_modules và build output đã được ignore. Issue tracker vẫn có thể giữ local markdown dù source nằm trên GitHub.

Hoàn thành khi GitHub có source và lockfile, tag v0.1.0, không có credential trong diff. Không commit token EAS, mật khẩu MySQL hoặc private key SSH.

2. Chuẩn bị VPS Linux và DNS

  1. Đề xuất Ubuntu 24.04 LTS, 2 vCPU / 4 GB RAM nếu build image ngay trên VPS; đây là điểm khởi đầu, chưa phải sizing từ benchmark.
  2. Cài Docker Engine và Docker Compose plugin theo hướng dẫn chính thức cho distro. Xác minh bằng docker version và docker compose version.
  3. Tạo user triển khai, thiết lập SSH key. Với repo private, dùng deploy key chỉ đọc hoặc cơ chế GitHub CLI phù hợp trên server.
  4. Trỏ A record của domain web và API về public IPv4 của VPS. Chỉ thêm AAAA nếu IPv6 thực sự hoạt động.
  5. Cho phép đúng cổng SSH đang dùng trước khi bật firewall; mở TCP 80/443 và tùy chọn UDP 443. Không mở database ra Internet.
  6. Đảm bảo cổng 80/443 chưa bị reverse proxy khác chiếm. Nếu VPS đã có Nginx/Caddy chung, tích hợp routing vào proxy hiện hữu thay vì chạy thêm stack chiếm cùng cổng.

Hoàn thành khi SSH và Docker hoạt động, DNS trỏ đúng và cổng chứng chỉ HTTPS được truy cập từ Internet.

3. Clone, cấu hình và triển khai phiên bản đầu

git clone git@github.com:OWNER/drinking-game-mobile.git
# Chuyển terminal vào thư mục vừa clone.
git checkout v0.1.0
cp .env.production.example .env.production
chmod 600 .env.production
openssl rand -hex 32
openssl rand -hex 32

Điền APP_DOMAIN, API_DOMAIN, ACME_EMAIL, hai mật khẩu sinh riêng và RELEASE_TAG=v0.1.0 vào .env.production. Giá trị mật khẩu khởi tạo MySQL chỉ áp dụng khi volume mới; sửa file env không tự đổi password trong database đã tồn tại. 

docker compose --env-file .env.production -f compose.production.yaml config --quiet
docker compose --env-file .env.production -f compose.production.yaml build
docker compose --env-file .env.production -f compose.production.yaml up -d --wait
docker compose --env-file .env.production -f compose.production.yaml ps
docker compose --env-file .env.production -f compose.production.yaml logs --tail=100 api web

curl --fail https://api.example.com/health
curl --head https://play.example.com

URL API được đưa vào web trong bước build, không phải lúc container khởi động. Thay domain API phải rebuild web; APK cũng cần build lại. MySQL tự tạo schema ban đầu và seed 50 lá khi API khởi động; các lần khởi động tiếp theo không ghi đè seed.

Caddy giữ chứng chỉ ở caddy_data; MySQL giữ dữ liệu ở mysql_data. Các volume thuộc project chamly-production, tách khỏi database local.

4. Nghiệm thu trên môi trường Linux

Kịch bản Kết quả mong đợi
Mở web bằng HTTPS Không mixed-content, không lỗi CORS; health trả status ok.
Hai máy ở hai mạng khác nhau vào cùng phòng Danh sách thành viên và lá bài cập nhật nhất quán, không chỉ hoạt động trong LAN.
Sai mật khẩu, sai lượt, người ngoài đoán mã Server từ chối.
Reload web hoặc tắt/bật mạng Vào lại đúng phòng và lượt khi token còn.
Restart container API trong phiên thử nghiệm Có gián đoạn kết nối ngắn, sau đó khôi phục đúng lá và lượt.
Expo Go / APK dùng URL API HTTPS Chơi chung với web; xác nhận trên điện thoại thật.
Backup và restore vào môi trường riêng Dữ liệu đọc được và tiến trình phục hồi đúng.

Tất cả kiểm tra trên VPS và domain thật đang chờ thông tin máy chủ; chưa có kết quả production.

5. Cập nhật phiên bản, rollback và backup

Phát hành

Giai đoạn đầu deploy thủ công bằng tag để giảm số thành phần. Mỗi bản cần chạy typecheck, unit, integration và UI tests trước khi tạo tag. Khi quy trình ổn định mới bổ sung GitHub Actions build image lên GHCR và deploy qua SSH/environment secrets. 

git fetch --tags origin
git checkout v0.1.1
# Đổi RELEASE_TAG=v0.1.1 trong .env.production
docker compose --env-file .env.production -f compose.production.yaml build
docker compose --env-file .env.production -f compose.production.yaml up -d --wait
curl --fail https://api.example.com/health

Build trước khi thay container để tránh dừng dịch vụ trong lúc build. Đây không phải zero-downtime deployment. Thử update ngoài thời điểm có phòng quan trọng.

Rollback

Giữ image/tag của bản trước. Checkout tag cũ, đổi RELEASE_TAG về bản đó, chạy up -d --no-build --wait và kiểm tra health. Nếu release có đổi schema hoặc định dạng JSON phòng, cần migration tương thích ngược hoặc phương án restore đã thử; không giả định rollback code tự rollback được dữ liệu.

Backup

mkdir -p backups
docker compose --env-file .env.production -f compose.production.yaml exec -T db sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" mysqldump -u "$MYSQL_USER" --single-transaction --no-tablespaces "$MYSQL_DATABASE"' > "backups/chamly-$(date +%Y%m%d-%H%M%S).sql"

Kiểm tra exit code và dung lượng file trước khi coi là thành công. Lập lịch backup hàng ngày, mã hóa và sao chép ra nơi khác; giữ tối thiểu các bản gần nhất phù hợp nhu cầu lưu phiên. Backup chứa hash phiên và mật khẩu phòng, chỉ cấp quyền cho người vận hành. Thử restore trên một stack riêng trước khi phục hồi vào database thật. Volume không thay thế backup; docker compose down -v sẽ xóa volume của stack được chỉ định.

Theo dõi vận hành

Giám sát HTTPS health endpoint, dung lượng ổ đĩa, trạng thái container và log lỗi API. Cấu hình mẫu giới hạn log từng container 3 file × 10 MB. Load test và chống abuse ở tầng public edge cần được đánh giá trước khi mở rộng số người dùng.

Thông tin cần chốt trước khi deploy thật

  • GitHub owner/repo, public hay private.
  • IP server, Linux distro, user SSH và cổng SSH.
  • Domain web và API; DNS đang được quản lý ở đâu.
  • Server đã có reverse proxy hoặc ứng dụng dùng cổng 80/443 chưa.
  • Nơi lưu backup ngoài VPS.
  • Tài khoản Expo/EAS để build APK.

Chưa chạy git init/commit/push và chưa truy cập server bên ngoài. Các cấu hình production sẽ được kiểm tra cú pháp/build local; việc cấp chứng chỉ và DNS chỉ kiểm chứng được khi có domain và VPS thật.
