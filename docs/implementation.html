Chạm Ly — MVP nhiều người chơi

Mỗi người nhập tên trên thiết bị riêng, tạo hoặc vào phòng có mật khẩu và cùng theo dõi một ván bài. Server NestJS quyết định trạng thái chung; MySQL giữ tiến trình để khôi phục sau khi backend khởi động lại.

1. Bức tranh tổng thể

  1. Nhập tên → cấp phiên khách, không cần tài khoản.
  2. Tạo phòng có tên và mật khẩu, hoặc vào bằng mã phòng và mật khẩu.
  3. Chủ phòng sửa bản sao bộ 50 lá; các phòng khác không đổi.
  4. Bắt đầu: chia bài úp, lần lượt mở bài và xác nhận kết quả.
  5. Thiếu bài: chủ phòng xáo lại hoặc kết thúc. Thiết bị mất mạng vào lại lấy trạng thái mới nhất.

Bản gốc là web React/Vite, nhập danh sách người chơi thủ công và lưu snapshot trên một trình duyệt. Bản gốc thực tế có 60 lá; MVP dùng card-1 đến card-50. Những lá có luật tương tác ngoài đời vẫn do cả bàn thực hiện.

2. Chạy tại máy phát triển

Yêu cầu Node.js 22.13+, npm, Docker Engine và Compose. Chạy các lệnh sau ở thư mục gốc dự án: 

npm ci
docker compose up -d --build
npm run web

Web tại localhost:45102, API health tại localhost:45100/health. Database chỉ bind loopback 127.0.0.1:45101. Để thử hai người, dùng hai browser context riêng (cửa sổ thường và ẩn danh), vì hai tab chung trình duyệt dùng cùng token lưu cục bộ.

Máy hiện tại đã cấu hình địa chỉ LAN 192.168.1.239. File apps/mobile/.env.local chứa EXPO_PUBLIC_API_URL; file .env chứa CORS_ORIGINS cho localhost và LAN. Địa chỉ LAN thay đổi thì cập nhật hai file và khởi động lại Expo/API. Các file này bị Git ignore. 

# Phát triển backend ngoài Docker, vẫn dùng MySQL container:
docker compose stop api
npm run api

# Kiểm thử:
npm run typecheck
npm run build:api
npm test
npm run test:integration
EXPO_OFFLINE=1 npm run export:web -w @chamly/app
npx playwright install chromium
npm run test:e2e

Test integration dùng database local trên cổng 45101, tạo dữ liệu riêng rồi dọn dữ liệu đó; một test khởi chạy backend thử nghiệm ở cổng 45105 để kiểm tra restart. Playwright mở hai trình duyệt thật và tự bấm UI. Ảnh nằm ở test-results/.

3. Quy ước MVP

  • Phòng từ 2 đến 12 người; tên người chơi không trùng trong cùng phòng.
  • Bộ riêng từ 2 đến 200 lá, phải đủ lá cho một vòng. Chỉ chủ phòng sửa tại lobby.
  • Chỉ thành viên đã có chỗ mới reconnect giữa ván; người mới chờ ván sau.
  • Chủ phòng rời chủ động: chuyển quyền cho thành viên tiếp theo. Chủ phòng offline: giữ quyền để reconnect; chưa có tự động chuyển quyền.
  • Chủ phòng có thể bỏ lượt hiện tại; các người chơi khác chỉ điều khiển lượt của mình.
  • Đồng hồ có một deadline từ server, hiển thị trên tất cả thiết bị; không tự xử thua khi hết giờ.
  • Thống kê số ngụm thuộc người đang ở lượt; việc chỉ định/ngụm của người khác không được tự động tính.
  • Phòng hết hạn sau 24 giờ từ thao tác thay đổi gần nhất, phiên đăng nhập hết hạn sau 7 ngày kể từ lúc tạo (không tự gia hạn). Lịch sử giữ 500 lượt gần nhất; UI hiển thị 20.

Các giới hạn và hành vi biên trên là mặc định triển khai MVP, chưa được duyệt riêng như yêu cầu nghiệp vụ lâu dài.

4. Kiến trúc hiện trạng

apps/mobile dùng React Native + Expo SDK 57 + NativeWind 4. apps/api dùng NestJS 11, Socket.IO 4 và mysql2. packages/shared là hợp đồng TypeScript giữa hai bên, không chứa mật khẩu hoặc trạng thái bí mật của phòng.

Thiết bị gửi command có requestId và revision. Backend xác thực token, khóa hàng phòng bằng SELECT FOR UPDATE, kiểm tra quyền và luật, cập nhật JSON rồi commit. Sau commit mới broadcast RoomView. Client bỏ snapshot có revision cũ hơn và lấy snapshot định kỳ mỗi 15 giây để khôi phục trường hợp bỏ lỡ sự kiện.

Bảng / dữ liệu Nội dung và vai trò
sessions UUID người chơi, tên, hash SHA-256 của token ngẫu nhiên 256-bit, expires_at.
default_decks Seed bộ mặc định 50 lá, INSERT IGNORE để không ghi đè nội dung đã có.
rooms Mã phòng, tên, mật khẩu scrypt có salt, aggregate JSON chứa thành viên/bài/lượt/thống kê, revision, receipt gần nhất và expires_at.
Bộ nhớ server Socket và trạng thái online. Không phải nguồn sự thật của tiến trình.
Thiết bị AsyncStorage cho metadata; native SecureStore cho token; web localStorage qua AsyncStorage. Không lưu tiến trình có thẩm quyền.

RoomView chỉ chứa nội dung các slot đã mở; thứ tự bài còn lại và nội dung từng slot úp không gửi xuống client. Nội dung danh mục bộ bài vẫn xem được, như bản cũ.

Triển khai hiện tại dùng một instance backend. Muốn scale nhiều instance cần adapter broadcast liên instance; MySQL lock đơn thuần không giải quyết việc gửi sự kiện giữa các process.

6. Expo Go và APK

npm start
# Quét QR bằng Expo Go phù hợp SDK 57.
# Điện thoại cùng Wi-Fi và phải truy cập được backend ở IP LAN.

Expo Go chạy bundle native từ Metro. Cổng 8081 phục vụ Metro/web; API dùng cổng 3000. Expo tunnel chỉ đưa Metro ra ngoài mạng, không tự đưa backend ra Internet. 

# Từ apps/mobile, sau khi có tài khoản Expo:
npx eas-cli login
npx eas-cli init
# Cấu hình EXPO_PUBLIC_API_URL cho môi trường EAS, trỏ tới backend thực.
npx eas-cli build --platform android --profile preview

eas.json có profile preview xuất APK. Preview cho phép HTTP LAN; production yêu cầu URL HTTPS. URL API được nhúng lúc build, thay đổi URL phải build lại. eas whoami hiện trả về Not logged in; chưa tạo build EAS hoặc file APK.
