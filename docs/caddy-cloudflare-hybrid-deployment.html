Chạy frontend trên host, backend bằng Docker và public qua Cloudflare

Production không nên public Expo development server từ npm run web. Frontend được export thành file tĩnh, Caddy phục vụ các file đó và chuyển các request API/WebSocket vào container backend. Cloudflare Tunnel chỉ cần trỏ vào một cổng Caddy duy nhất.

1 hostname
Web, REST và Socket.IO cùng domain
1 public port
Chỉ origin Caddy tại 127.0.0.1:45104
0 inbound
Không mở port router hoặc firewall Internet
Lệnh public cuối cùng: cf-deploy chamly chamly --mode port --port 45104. Cờ --mode port được ghi rõ vì repo có compose.yaml; nếu chỉ truyền -p, chế độ tự nhận diện có thể ưu tiên Compose trước chế độ port.

Các đường dẫn /health, /sessions, /auth/* và /socket.io/* được reverse proxy tới NestJS. Caddy tự chuyển tiếp WebSocket upgrade, không cần cấu hình header thủ công.

2. Caddy là gì và nằm ở đâu

Caddy là web server và reverse proxy, cùng nhóm vai trò với Nginx hoặc Apache. Trong kiến trúc này, Caddy là cổng vào duy nhất của ứng dụng trên máy host: vừa phục vụ frontend tĩnh, vừa quyết định request nào phải chuyển sang backend.

Caddy trong apps/mobile/Dockerfile hiện là Caddy chạy trong container web. Runbook này dùng Caddy cài trên host để đáp ứng đúng mô hình frontend ngoài Docker. Hai mô hình là lựa chọn thay thế, không chạy đồng thời trên cùng cổng 45104.

3. Chuẩn bị máy production

3.1 Điều kiện

  • Node.js 22+, Docker Engine, Docker Compose v2, Git, curl và jq.
  • cloudflared đã login bằng user triển khai; có ~/.cloudflared/cert.pem.
  • Các script ~/.local/bin/cloudflare-deploy, cloudflare-publish và template ~/.config/systemd/user/cloudflared-app@.service đã được cài.
  • Domain banhchungranchaydenxi.click đang Active trên Cloudflare.

3.2 Cài Caddy từ repository chính thức

sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl

curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' \

4. Chạy backend và MySQL bằng Docker

Phải sửa mapping API trước production. compose.yaml hiện dùng '${API_PORT:-45100}:45100', mặc định bind 0.0.0.0 và có thể mở API ra LAN. Đổi thành '127.0.0.1:${API_PORT:-45100}:45100'. Mapping MySQL hiện đã bind loopback đúng cách. 
cd /home/kensnows/Learning/drinking_game_mobile
docker compose --env-file .env -f compose.yaml config --quiet
docker compose --env-file .env -f compose.yaml up -d --build --wait
docker compose --env-file .env -f compose.yaml ps
curl -i http://127.0.0.1:45100/health

Backend phải trả 200 {"status":"ok"} trước khi cấu hình Caddy. Lệnh tắt là docker compose --env-file .env -f compose.yaml down; không thêm -v vì cờ đó xóa volume MySQL.

5. Build frontend ngoài Docker

Lệnh export tạo bundle production trong apps/mobile/dist. API URL dùng cùng hostname public để browser chỉ giao tiếp same-origin qua Caddy.

cd /home/kensnows/Learning/drinking_game_mobile
npm ci
EXPO_PUBLIC_API_URL=https://chamly.banhchungranchaydenxi.click \
  npm run export:web -w @chamly/app

sudo install -d -o root -g caddy -m 0755 /srv/chamly
sudo rsync -a --delete apps/mobile/dist/ /srv/chamly/
sudo chown -R root:caddy /srv/chamly
sudo find /srv/chamly -type d -exec chmod 0755 {} +
sudo find /srv/chamly -type f -exec chmod 0644 {} +
Không dùng npm run web cho production. Lệnh đó mở Expo dev server ở cổng 45102, có hot reload và lifecycle phụ thuộc terminal. Nó phù hợp phát triển cục bộ, không thay thế static build + process manager.

6. Cấu hình và kiểm tra Caddy

Ghi nội dung sau vào /etc/caddy/Caddyfile. Caddy chỉ nghe loopback để mọi traffic ngoài máy buộc phải đi qua Cloudflare.

http://127.0.0.1:45104 {
    encode zstd gzip

    @api path /socket.io/* /health /sessions /auth/*
    handle @api {
        reverse_proxy 127.0.0.1:45100
    }

    handle {
        root * /srv/chamly
        header /index.html Cache-Control "no-cache"
        try_files {path} /index.html
        file_server
    }
}

Validate trước khi reload

sudo caddy fmt --overwrite /etc/caddy/Caddyfile
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy

Kiểm tra origin hợp nhất

curl -I http://127.0.0.1:45104/
curl -i http://127.0.0.1:45104/health
curl -i "http://127.0.0.1:45104/socket.io/?EIO=4&transport=polling"

Nếu cấu hình mới lỗi, validate chặn trước khi reload. Log nằm trong journal: journalctl -u caddy -n 100 --no-pager.

7. Public Caddy bằng cf-deploy

7.1 Nạp shell function và chạy dry-run

source ~/.bashrc
cf-deploy chamly chamly --mode port --port 45104 --dry-run

Kế hoạch phải in origin http://127.0.0.1:45104 và public URL https://chamly.banhchungranchaydenxi.click.

7.2 Tạo tunnel, DNS, ingress và service

cf-deploy chamly chamly --mode port --port 45104

Script kiểm tra origin, tạo hoặc dùng tunnel chamly, tạo CNAME, ghi config ~/.cloudflared/apps/chamly.yml, validate ingress, restart cloudflared-app@chamly.service và kiểm tra URL HTTPS. Mỗi hostname có tunnel riêng nên dừng Chạm Ly không ảnh hưởng tunnel tài liệu hoặc app khác.

7.3 Kiểm tra đầu cuối

cf-deploy list
cf-publish-status chamly 45104 /health
curl -i https://chamly.banhchungranchaydenxi.click/health
curl -i "https://chamly.banhchungranchaydenxi.click/socket.io/?EIO=4&transport=polling"
systemctl --user status cloudflared-app@chamly.service

Sau các lệnh HTTP, mở hai trình duyệt hoặc hai thiết bị ở hai mạng khác nhau và chơi cùng một phòng để xác nhận WebSocket thật sự hoạt động.

9. Các điểm cần xử lý trước production thật

API đang bind ra mọi interface host trong compose development

Đổi mapping API sang 127.0.0.1:${API_PORT:-45100}:45100. Nếu không, thiết bị trong LAN có thể gọi API trực tiếp và bỏ qua Caddy/Cloudflare.

Rate limit hiện có nguy cơ gộp mọi người dùng thành một IP

Route /sessions giới hạn theo req.ip, nhưng request đi qua Cloudflare, cloudflared và Caddy. Backend hiện chưa cấu hình trust proxy hoặc đọc CF-Connecting-IP; vì vậy mọi người dùng có thể bị nhìn thành địa chỉ proxy nội bộ và cùng chia sẻ giới hạn 20 request/phút. Cần sửa backend và thêm test trước khi coi cấu hình này production-ready.

Script cf-deploy phụ thuộc máy đã cài sẵn bộ helper

Script và systemd template hiện nằm trong home của user, không nằm trong repo. Khi chuyển sang VPS khác, cần cài/copy bộ helper, login Cloudflare trên VPS, hoặc dùng phương án cloudflared container/token trong DEPLOYMENT.md. Không thể chỉ clone repo rồi gọi cf-deploy trên một máy sạch.

Không chạy trùng tunnel UUID trên máy cũ và máy mới

Cloudflare coi đó là nhiều connector và có thể chia request giữa hai máy. Khi chuyển production, dừng connector cũ hoặc tạo tunnel production riêng.
