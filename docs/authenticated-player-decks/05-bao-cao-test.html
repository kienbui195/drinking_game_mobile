Test theo từng AC

Tất cả AC dưới đây đều tự test được (unit/integration/e2e chạy trong môi trường hiện tại) — không có AC nào cần thao tác tay trên thiết bị vật lý. Bằng chứng dẫn thẳng tới file và dòng test. AC-01.2 và US-07 (username bất biến) có ghi chú vì nghiệp vụ thật đã thay đổi so với câu chữ AC gốc trong 02-giai-phap-us-ac.html.

Chạy toàn bộ test sẵn có (bắt hồi quy)

Không có test cũ nào bị hỏng bởi thay đổi của việc này.

# npm run typecheck

@chamly/api typecheck ✓   @chamly/app typecheck ✓   exit 0

# npm test (engine.test.ts)

# tests 9 · # pass 9 · # fail 0

# npm run test:integration

# tests 3 · # pass 3 · # fail 0

# ADMIN_PASSWORD=*** npm run test:e2e

✓ admin.spec.ts > admin gate needs the right password

✘ admin.spec.ts > admin dashboard lists rooms (xem mục nợ)

✓ multiplayer.spec.ts > create, edit, join, play, resume

✓ pouch.spec.ts > keepable card stashed and played later

3 passed, 1 failed (do môi trường)

tests/multiplayer.spec.ts, tests/pouch.spec.ts và tests/admin.spec.ts đã được cập nhật để đăng ký tài khoản + tạo/chọn deck thay cho luồng nhập tên ẩn danh cũ đã bị gỡ khỏi giao diện; trước khi sửa, cả ba đều treo/fail ngay ở bước đăng nhập vì nhãn nút/field không còn khớp giao diện mới — đây là một bug đã sửa trong việc này, không phải test mới viết thêm cho có.

Đánh giá ảnh hưởng hệ thống hiện tại

  • Bảng sessions (đã có từ trước) — chỉ thêm 2 cột NULL được (user_id, started_at), không đổi cột cũ. Luồng phiên ẩn danh cũ (POST /sessions, dùng bởi test "real MySQL + sockets…") vẫn chạy nguyên vẹn — đã xác nhận qua test 1 vẫn pass.
  • Kiểu Session / Reply<T> (packages/shared) — chỉ thêm field optional (username?, nextAllowedAt?), đã rà AdminDashboard.tsx và RoomScreen.tsx — không nơi nào giả định shape cũ cố định, không có phá vỡ.
  • GameEngine / phòng chơi thời gian thực — không đổi state machine; thay đổi duy nhất là nguồn bộ bài khởi tạo phòng (từ deck cá nhân snapshot thay vì luôn luôn từ deck mặc định). Toàn bộ test cũ về timer, lượt chơi, túi thần kỳ, resume sau restart (test 1 và test 3) vẫn pass nguyên trạng.
  • Admin dashboard / thông báo phòng — không đổi logic, nhưng phụ thuộc gián tiếp vào giao diện đăng nhập mà việc này đã thay thế hoàn toàn (bỏ luồng "chỉ nhập tên"). Đây là lý do tests/admin.spec.ts phải sửa theo — đã sửa, xem mục "Toàn bộ test sẵn có".
  • apps/mobile/src/connection.ts — thêm phát hiện hostname LAN riêng tư khi chạy web dev, không đổi hành vi production (giữ nguyên EXPO_PUBLIC_API_URL khi hostname không phải localhost/LAN riêng tư).

Việc còn nợ

  • Sub-test "admin dashboard lists rooms and can manage them" đang fail vì môi trường, không phải code. Tiến trình API dev đang chạy nền (PID phát hiện lúc kiểm thử, khởi động lúc 15:46) không có biến ADMIN_PASSWORD trong environment của chính nó (đã xác nhận bằng /proc/<pid>/environ) — nên adminPassword() trả về chuỗi rỗng và mọi mật khẩu admin đều bị từ chối, kể cả mật khẩu đúng trong .env. Cách xử lý: restart tiến trình API dev với .env được load (ví dụ dừng process hiện tại rồi chạy lại npm run api từ shell đã source .env, hoặc chuyển hẳn sang chạy qua docker compose). Chưa tự làm vì tiến trình đó có thể đang được một phiên làm việc khác (Codex) dùng — cần user xác nhận trước khi khởi động lại.
  • Luồng phiên ẩn danh (chỉ nhập tên, endpoint POST /sessions) vẫn còn trong code nhưng không còn lối vào từ giao diện mobile. Đây là quyết định thiết kế hợp lý (toàn bộ US-01..US-07 giả định có tài khoản), nhưng chưa có xác nhận rõ ràng từ user là có nên gỡ hẳn endpoint/luồng đó khỏi backend hay giữ lại để tương thích ngược cho các bản ứng dụng cũ đã cài trên máy người chơi thật. Đề xuất: giữ nguyên cho tới khi biết chắc không còn thiết bị nào dùng bản cũ.
  • 04-handoff.md chưa từng được tạo vì user chọn "tôi code" trực tiếp ở cổng 4 thay vì bàn giao cho AI/dev khác — theo đúng quy trình, file này chỉ bắt buộc khi chọn nhánh "người khác code". Không phải thiếu sót.

Bước tiếp theo cần user xác nhận trước khi merge vào main: (1) đồng ý coi bước 5 đã đạt dù có 1 sub-test admin fail do môi trường (không do code việc này); (2) quyết định có restart tiến trình API dev để chạy lại đúng sub-test đó cho sạch hay chấp nhận bằng chứng phân tích qua /proc/<pid>/environ; (3) quyết định giữ hay gỡ endpoint phiên ẩn danh cũ. Sau khi có xác nhận, chuyển sang Bước 6 (chốt AC, merge theo đúng quy trình phát hành đã duyệt ở 02-giai-phap-us-ac.html: build/export/test → merge vào main → build production từ main).
